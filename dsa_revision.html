⚡ Hash Maps & Sets

Trade space for time: turn linear searches into constant-time lookups using sets or frequency maps.

Remember what you have seen

Use when: the question asks whether a value, complement, or frequency has appeared before.

Why it works

A set or dictionary turns a full scan for the previous value into an average O(1) lookup. The loop only moves forward once.

seen = set()for x in nums:    if x in seen: return True    seen.add(x)

Sub-Techniques to Recognize

Record each visited number in a set. If the current number already exists in the set, a duplicate is immediately identified in O(1) average time.

⚡ Prefix & Suffix Accumulation

Avoid repeated passes and nested loops by pre-aggregating cumulative prefix/suffix values or identifying streak roots.

Build information once

Use when: each answer depends on everything to the left or right, or repeated work is hiding inside a nested loop.

Why it works

A prefix or suffix stores the accumulated result before the current index. Each position then combines two ready-made answers in O(1).

prefix = 1for i in range(n):    answer[i] = prefix    prefix *= nums[i]

📈 Dynamic Programming: Overview & Blueprint

Name the state, write the transition, and keep only the history the next decision actually needs.

Python 3 ▾ 
def solve(states: List[int]) -> int:    """    states: [s0, s1, s2, s3, ...]    Only store minimal history (prev2, prev1) to reach next state    """    prev2, prev1 = 0, 0    for state in states:        current = transition(prev2, prev1, state)        prev2, prev1 = prev1, current    return prev1  # keep only useful history

📈 1D State Transitions

Summarize the subproblem into minimal state variables and advance through transitions without recomputing overlapping branches.

State + transition

Use when: the answer at position i depends on a small, fixed amount of earlier work.

Why it works

The state summarizes every relevant way to reach the current position. The transition considers the allowed previous moves exactly once.

prev2, prev1 = 0, 0for value in nums:    prev2, prev1 = prev1, max(prev1, prev2 + value)
Core Techniques

Sub-Techniques to Recognize

Climbing Stairs (Linear)

Each step is reached from i-1 or i-2. Add combinations iteratively to calculate distinct ways in linear time.

When computing dp[i] = max(dp[i-1], dp[i-2] + val), retain only two scalar variables rather than an entire array.

Choose, skip, or carry

🥞 Stack & Queue: Overview & Blueprint

Use LIFO order for nested/backtracking state and FIFO/deque for ordered streams; apply monotonic invariants to eliminate dominated candidates in O(1) amortized time.

Python 3 ▾ 
from collections import dequedef processMonotonic(nums: List[int], k: int) -> List[int]:    """    Stack & Queue Invariants    ------------------------    1. Monotonic Stack (Next Greater):       nums:   [2,  1,  2,  4,  3]       stack:  [4] (stores candidates; pops smaller items)       result: [4,  2,  4, -1, -1]    2. Monotonic Deque (Sliding Window Max, k=3):       window: [1, 3, -1] -> deque: [3, -1] -> max: 3       Next 5: 3 and -1 are smaller & older -> pop -> deque: [5]    """    # Monotonic Decreasing Stack: Next Greater Element    n = len(nums)    next_greater = [-1] * n    stack = []  # stores indices    for i, val in enumerate(nums):        while stack and nums[stack[-1]] < val:            prev_idx = stack.pop()            next_greater[prev_idx] = val        stack.append(i)    return next_greater

🥞 Monotonic Stack

Maintain elements in strictly increasing or decreasing order to identify nearest greater or smaller neighbors in linear amortized time.

Next / previous greater or smaller element

Use when: finding the next warmer temperature, next greater number, previous smaller element, or bounding rectangle widths in a histogram.

Why it works & Visual Trace

Each element is pushed once and popped at most once $\implies$ amortized O(n) total time. When an incoming element violates monotonicity, it serves as the exact "next greater" value for all smaller elements waiting on the stack!

Array:  [73,  74,  75,  71,  69,  72,  76,  73]
Stack:  Monotonically decreasing (waiting for warmer day)

Day 0 (73): stack=[(0:73)]
Day 1 (74): 74 > 73 -> POP 73! Next warmer day for Day 0 is Day 1 (span: 1).
            stack=[(1:74)]
Day 2 (75): 75 > 74 -> POP 74! Next warmer day for Day 1 is Day 2 (span: 1).
            stack=[(2:75)]
Day 3 (71): 71 < 75 -> PUSH. stack=[(2:75), (3:71)]
Day 4 (69): 69 < 71 -> PUSH. stack=[(2:75), (3:71), (4:69)]
Day 5 (72): 72 > 69 -> POP 69! Day 4 answer is Day 5 (span: 1).
            72 > 71 -> POP 71! Day 3 answer is Day 5 (span: 2).
            72 < 75 -> PUSH. stack=[(2:75), (5:72)]
stack = []  # stores indices of candidate temperaturesans = [0] * len(temperatures)for i, t in enumerate(temperatures):    while stack and temperatures[stack[-1]] < t:        prev_i = stack.pop()        ans[prev_i] = i - prev_i    stack.append(i)

Sub-Techniques to Recognize

🥞 Monotonic Queue & Deque

Maintain an ordered double-ended queue to query sliding window extrema and optimal prefix boundaries in constant time per step.

Sliding window optimum with purge

Use when: tracking the maximum or minimum in a moving window of size k, or optimizing prefix sum ranges under a constraint.

Why it works & Visual Trace

If element A is older than B ($idx_A < idx_B$) and $val_A \le val_B$, A can never be the maximum in any current or future window containing B. Popping dominated back elements keeps the deque strictly decreasing; the front always yields the window maximum in O(1)!

nums = [1,  3, -1, -3,  5,  3,  6,  7],  k = 3

i=0 ( 1): q = [0: 1]
i=1 ( 3): 3 > 1 -> POP back. q = [1: 3]
i=2 (-1): -1 < 3 -> PUSH.    q = [1: 3, 2:-1]          -> Window 0..2 Max: nums[q[0]] = 3
i=3 (-3): -3 < -1 -> PUSH.   q = [1: 3, 2:-1, 3:-3]    -> Window 1..3 Max: nums[q[0]] = 3
i=4 ( 5): Drop expired idx 1 (1 < 4-3+1).
          5 > -3 and 5 > -1 -> POP both! q = [4: 5]     -> Window 2..4 Max: nums[q[0]] = 5
i=5 ( 3): 3 < 5 -> PUSH.     q = [4: 5, 5: 3]          -> Window 3..5 Max: nums[q[0]] = 5
i=6 ( 6): 6 > 3 and 6 > 5 -> POP both! q = [6: 6]     -> Window 4..6 Max: nums[q[0]] = 6
q = deque()  # stores indices; values strictly decreasingres = []for i, x in enumerate(nums):    while q and q[0] < i - k + 1:        q.popleft()  # drop expired front    while q and nums[q[-1]] <= x:        q.pop()      # drop dominated smaller back items    q.append(i)    if i >= k - 1:        res.append(nums[q[0]])

Purge smaller elements from the back upon arrival, and drop expired elements from the front on sliding. Deque head always yields window optimum in O(1).
