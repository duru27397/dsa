⚡ Permutation Cycles & In-Place Swapping

Deconstruct array permutations into disjoint directed graph cycles: shift or transpose elements directly into target positions in strictly linear time and O(1) auxiliary space.

⚡ The Permutation Cycle Principle

Governing Principle: Any one-to-one rearrangement (permutation) of N elements decomposes into a set of strictly disjoint, closed directed cycles. Because each element has strictly one source and one destination (in-degree = 1, out-degree = 1), traversal along edges i → π(i) is mathematically guaranteed to return to the starting origin without branching, collisions, or dead ends. Resolving an array in-place is the physics of closing these isolated circular loops.

Formal Proof: Why Permutation A → B Decomposes into Disjoint Cycles

Use when: Transforming array A into target array B with identical elements, and proving why the directed graph MUST consist of independent closed cycles with zero overlapping nodes.

Concrete Example & Visual Transformation Trace (A → B)

Consider Source Array A = [40, 10, 30, 20] and Target Array B = [10, 20, 30, 40] at indices 0, 1, 2, 3. Each element in A maps to a target destination slot in B where that value belongs:

1️⃣ The Degree Invariant (Bijective Graph)

In directed graph G = (V, E) where vertices are index slots {0, 1, ..., N-1} and directed edges are i → π(i):
• Every index i in A has exactly one target position in B &implies; out-degree(i) = 1.
• Because B has the exact same elements as A (bijection), every target slot in B receives exactly one element &implies; in-degree(j) = 1.
• Zero branching (no vertex splits) and zero convergence (no vertices collide).

2️⃣ Why it MUST Loop (Pigeonhole Principle)

Start at any vertex v0 and walk along directed edges: v0 → v1 → v2 → ...
• Because the vertex set is finite (|V| = N), by the Pigeonhole Principle, a vertex must eventually repeat within N hops.
• Why no "lasso" (ρ) tail? If the loop closed at an intermediate node vk (k > 0), that node would have two incoming edges (from the start path and from the loop), violating in-degree = 1!
• Thus, the first repeat MUST be v0 itself. The walk forms a pure, tail-free cycle.

3️⃣ Why Cycles are Strictly Disjoint

Suppose two cycles C1 and C2 shared a common vertex X:
• If X had two outgoing edges (one into C1 and one into C2), out-degree(X) ≥ 2.
• If two incoming edges entered X, in-degree(X) ≥ 2.
• Both violate the in-degree = out-degree = 1 invariant.
• Therefore, every vertex belongs to exactly one cycle. The permutation graph partitions the array into strictly independent orbits.

4️⃣ Transposition Splitting Proof: Min Swaps = N - C

A swap of two elements at indices u, v is an algebraic transposition τ = (u, v):
• Same cycle: Swapping two elements in a cycle of length L splits it into two disjoint cycles of lengths k and L - k (ΔC = +1).
• Different cycles: Swapping elements in different cycles merges them into one cycle (ΔC = -1).
• The target sorted state consists of N cycles of length 1 (Ctarget = N).
• Because each swap increases cycle count by at most +1, the minimum swaps to reach N cycles from C cycles is strictly N - C.

The Unified Permutation Cycle Engine

Use when: Rearranging an array in-place without allocating auxiliary memory (cyclic shifts, transpositions to sorted order, or calculating minimum swaps to transform).

The Graphical Intuition: Array Boxes to Disjoint Circle Graphs

Consider an array of boxes with values and indices. A permutation directs each index i to its target destination π(i). Because every index has exactly one incoming pointer and one outgoing pointer, the graph separates into completely independent circular orbits.

O(N) Time · O(1) Space 
Mapping: π(i) = (i + k) % n
Total Disjoint Cycles: gcd(n, k)

O(N log N) Sort · O(N) Space 
Mapping: π(i) = getTargetIdx(currIdx)
Disjoint Cycles: C cycles of lengths L_1, L_2, ...
Swaps Invariant: Exactly (L - 1) swaps per cycle

Mechanism: "Target Cycle Traversal"
• Follow nxtIdx = getTargetIdx(currIdx) around cycle
• Mark visited[currIdx] = True to track traversed paths
• Cycle of length L requires exactly L - 1 swaps
• Advance cycleStartIdx; skip already visited nodes
• Total Swaps = Σ(L - 1) = N - C
Shared Concept: Sorting identifies each node's destination in the permutation graph. Each 2-element swap resolves one node of a cycle until the cycle contracts to a fixed point.
⚡ The 1:1 Unified Code Template: Right Shift, Left Shift & Sorting
Universal Engine

Technically, Left Shift, Right Shift, and Sorting/Transformation are the exact same algorithm. Every cycle in a permutation graph is resolved by following the directed target function nxtIdx = getTarget(currIdx) and depositing/swapping the displaced element into its destination. Only the definition of getTarget changes: 

# =========================================================================
# THE EXACT SAME REUSABLE PERMUTATION ENGINE (Single Unified Function)
# =========================================================================
def applyPermutation(nums: List[int], getTargetIdx) -> int:
    n, swaps = len(nums), 0
    visited = [False] * n

    for cycleStartIdx in range(n):
        # Skip if element was already processed in a previous cycle
        if visited[cycleStartIdx] or getTargetIdx(cycleStartIdx) == cycleStartIdx:
            continue

        currIdx, prevVal = cycleStartIdx, nums[cycleStartIdx]

        while True:
            visited[currIdx] = True
            nxtIdx = getTargetIdx(currIdx)
            prevVal, nums[nxtIdx], currIdx = nums[nxtIdx], prevVal, nxtIdx
            swaps += 1

            if currIdx == cycleStartIdx:
                break

        swaps -= 1  # Exactly L - 1 swaps per cycle of length L

    return swaps

# 1. ROTATE RIGHT: nxtIdx = (sourceIdx + k) % n
applyPermutation(nums, lambda sourceIdx: (sourceIdx + k) % len(nums))

# 2. ROTATE LEFT:  nxtIdx = (sourceIdx - k) % n
applyPermutation(nums, lambda sourceIdx: (sourceIdx - k) % len(nums))

# 3. SORT ARRAY:   nxtIdx = destinations[sourceIdx]
swaps = applyPermutation(nums, lambda sourceIdx: destinations[sourceIdx])

Cyclic Replacements (In-Place Array Rotation)

Use when: Shifting array elements right by k steps in O(n) time and O(1) space without allocating auxiliary buffer arrays.

Why it works & Graphical Circular Orbit Trace

Moving each element to (i + k) % n forms circular orbits. If gcd(n, k) = 1, all n indices belong to a single giant circular track. If gcd(n, k) > 1, the array breaks into exactly gcd(n, k) independent, non-intersecting circular tracks. Traversing Orbit 0 never modifies or touches Orbit 1. Tracking shifted == n guarantees every element is moved exactly once in O(n) time and O(1) auxiliary space.

class Solution:    def rotate(self, nums: List[int], k: int) -> None:        """        Rotate array in-place via Cyclic Replacements. Minimum Swaps to Transform (Cycle Decomposition)

Use when: Calculating the minimal number of element swaps required to sort an array or transform array A into target array B.

Why it works & Graphical Cycle Shrinkage Invariant

Each cycle of length L represents a closed loop of mismatched elements. Traversing the directed orbit nxtIdx = getTargetIdx(currIdx) uncovers all elements belonging to that disjoint cycle. Resolving a cycle of length L requires exactly L - 1 swaps (or transpositions). With visited tracking preventing duplicate traversals across irregular cycles, Total Swaps = Σ(Li - 1) = N - C.

Core Principles

Dynamic Programming Decision Framework

1. When to Use DP vs Greedy

Prerequisites: Overlapping subproblems + optimal substructure.

Two Spotting Signals

• Target Question: Asks for Min/Max, Count of Ways, Longest/Shortest, or Feasibility.
• Decision Dependency: Earlier choices constrain future options (e.g. House Robber: robbing house i forbids house i+1). If greedy choice isn't guaranteed optimal, use DP.

2. The 3-Step Framework

Method: State → Transition → Base Cases.

Step-by-Step Formulation

• 1. State Definition: Define dp(i, ...) using only relevant variables (e.g. current stair step).
• 2. Recurrence Relation: Express dp[i] in terms of previous states: dp[i] = dp[i-1] + dp[i-2].
• 3. Base Cases: Smallest states solvable directly (e.g. dp[1] = 1, dp[2] = 2).

3. Top-Down vs Bottom-Up

Top-Down: Recursion + Memo.
Bottom-Up: Iteration + Tabulation.

Trade-offs & Selection

• Top-Down (@cache): Intuitive to write; subproblem order doesn't matter; computes only reachable states.
• Bottom-Up (Iteration): Faster (zero call stack overhead); enables O(1) space optimization by tracking only last k states.

The Two Fundamental Engines

Architectural Models: Volume vs. Measurement

Architecture 1: The Combinatorics Basket (Addition)

Use when: "How many ways?", "Total combinations", "Count valid paths".

The Goal: Total Volume

You are not looking for the "best" path—you are finding every path. Never use max() or min(), and never add 1 +. Simply sum the universes together.

Greedy vs DP Strategy

When Can DP Be Compressed into Greedy?

The Danger of "Always": The Jump Game Trap

Myth: "If there are no capacity/weight limits, I can always use Greedy."

Why Pure Greedy Fails on Jump Game II

Consider nums = [2, 3, 1, 1, 4]:
• At index 0, value is 2. A greedy choice says: "Jump the maximum (2 steps) to index 2!"
• But index 2 holds a 1 (requiring 1 step then 1 step → 3 jumps total).
• If you jumped 1 step to index 1 (value 3), you could leap directly to the end in 2 jumps!
Lesson: The immediate local greedy choice locked you out of a better geometric position.

The Architect's 3-Step Greedy Checklist

Goal: Prove whether an O(n log n) Greedy loop can replace an O(n²) DP multiverse.

Checklist (Must Pass All 3)

1. Is the problem asking for a Global Extreme?
Must ask for Min, Max, Longest, or Shortest. If it asks for "Number of ways", Greedy is impossible → use DP.

2. Is there a strict Mathematical Tipping Point?
Can you write an exact condition where an option is mathematically proven bad (e.g. negativeDish > sumOfPositives)? If yes, an if break replaces branching.

3. Does Sorting Organize the Tipping Point?
Greedy almost always requires sorted input so all worse choices are clustered. If the problem forbids reordering (e.g. LIS), simple Greedy fails.

Array & String Physics

Subarray vs. Subsequence Invariants

1. Subarray / Substring (Contiguous)

The Rule: No gaps allowed. Elements must sit strictly adjacent.

The Physics: Extend or Restart

The worker cannot skip an item! If an item is refused, the current streak dies permanently.
• Engine: Either extend the streak with the current element, or restart a brand new streak from scratch (e.g. Kadane's dp[i] = max(x, dp[i-1] + x), Maximum Product Subarray).

2. Subsequence (Non-Contiguous)

The Rule: Gaps are legally allowed. Relative order is preserved.

The Physics: Take or Skip

The worker evaluates an item. If skipped, the historical streak stays alive in the pocket as they advance to the next index.
• Explicit Take/Skip: take = ..., skip = dp(index + 1) (0/1 Knapsack, LCS).

Why it works & The Reverse Loop Invariant

Capacity: [0, 1, 2, 3, 4, 5]

Coin = 2:

Longest Increasing Subsequence (O(n²) Jump Loop)

Use when: Finding longest subsequence under custom transition rules where binary search is not applicable, or when n ≤ 2500.

Why it works & Subsequence Jump Physics

In subsequence problems, skipping elements does not break continuity. The inner loop for j in range(i) acts as an implicit jump: checking whether nums[j] < nums[i] allows nums[i] to extend any valid previous subsequence ending at j, effectively skipping all elements between j and i.

nums = [10, 9, 2, 5, 3, 7]

def lengthOfLISQuadratic(nums: List[int]) -> int:    """    LIS O(n^2): Quadratic jump loop checking all valid predecessors.    dp[i] = length of longest increasing subsequence ending at index i. num = 2  -> 2 < 9,  replace -> tails: [2]
num = 5  -> 5 > 2,  append  -> tails: [2, 5]
num = 3  -> 3 < 5,  replace -> tails: [2, 3]   <-- Lower tail for len 2!
num = 7  -> 7 > 3,  append  -> tails: [2, 3, 7]
num = 101-> 101 > 7,append  -> tails: [2, 3, 7, 101]
num = 18 -> 18 < 101,replace-> tails: [2, 3, 7, 18]  <-- Lower tail for len 4!

Result: len(tails) = 4

Core Mechanics & Optimizations

How Nodes, Path Compression & Rank Work

1. Disjoint Forest Representation

The Concept: Elements are nodes in an up-tree directed forest.

Self-Root Representation

Every node i is initialized pointing to itself: parent[i] = i. A component's representative (root) is the unique node where parent[root] == root. Merging sets simply attaches one root under another.

2. Path Compression Optimization

The Invariant: Why re-climb a tall tree? Flatten paths during find.

Recursive Flattening

During find(x), as recursion unwinds, every visited ancestor updates its parent pointer directly to the root: parent[x] = find(parent[x]). Subsequent queries run in O(1) depth.

The Invariant: Always attach the shorter tree beneath the taller tree.

Theoretical Foundation

What is the Inverse Ackermann Function α(n)?

1. The Ackermann Function A(m, n)

Definition: A hyper-exponential mathematical function that grows faster than any tower of powers.

Astronomical Explosion

• A(1, n) = n + 2 (Linear)
• A(2, n) = 2n + 3 (Multiplication)
• A(3, n) = 2^(n+3) - 3 (Exponentiation)
• A(4, n) = 2^(2^(2^...)) - 3 (Tower of 2s of height n + 3)
Specifically, A(4, 2) = 2^65536 - 3, a number with ≈ 19,729 decimal digits!

2. The Inverse α(n) Definition

Definition: The inverse α(n) is the smallest k such that A(k, k) ≥ n.

Why α(n) ≤ 4 in Real Life

Because A(4, 4) is so unimaginably colossal (vastly exceeding 10⁸⁰, the total number of atoms in the observable universe):
• For all n ≤ 10⁸⁰, α(n) ≤ 4.
• In any practical computer program, α(n) will never exceed 4.
• Thus, O(α(n)) is mathematically amortized but practically identical to O(1).

3. Optimization Synergies

Synergy: Why both Path Compression and Union by Rank are required.

Complexity Breakdown

• Neither: O(n) per operation (degenerates into linked list).
• Rank Only: O(log n) strictly bounded tree height.
• Path Compression Only: O(log n) amortized.
• Both Combined: O(α(n)) amortized near-constant time.

Architectural Comparison

Union-Find vs. BFS vs. DFS: When & Why

1. Dynamic Connectivity (UF Superpower)

The Core Advantage: Edge additions arrive dynamically in a stream or online query.

Incremental O(α(n)) vs Full O(V + E)

• Union-Find: Adding an edge and checking if two nodes connect takes O(α(n)) ≈ O(1).
• BFS/DFS: Must re-traverse the graph from scratch on every new edge, costing O(E · (V + E)) = O(V · E + E²). Unusable for online edge streams!

2. What Can't You Do Without UF?

Exclusive Strengths: Problems that become intractable without Disjoint Sets.

Where UF Dominates BFS/DFS

• Kruskal's MST: Sort edges and test if adding edge forms a cycle in O(1). (BFS/DFS cycle check is O(V) per edge → O(E · V) vs O(E log E)).
• Real-Time Cycle Detection: If find(u) == find(v), edge (u, v) is instantly redundant.
• Offline Reverse-Time Queries: Turn edge deletions (e.g. crumbling grids, falling bricks) into additions by running time backwards!

3. What BFS / DFS Can Do That UF Cannot

Hard Limitations: Scenarios where Union-Find is fundamentally the wrong tool.

Where BFS / DFS Are Required

• Path Reconstruction: UF only tells you if two nodes are connected; it cannot produce the actual path or edge sequence.
• Shortest Paths / Step Distances: BFS guarantees the minimum hops in unweighted graphs; UF has no concept of distance.
• Directed Graphs: Standard UF only models symmetric equivalence relations (A ~ B ⟺ B ~ A). It cannot model DAGs, topological sort, or SCCs (Tarjan/Kosaraju).

The Universal Physics of Intervals

Core principle: an interval [s, e] is a continuous 1D range. Without ordering, detecting overlap requires checking every pair against each other (O(n2)). Sorting imposes a geometric arrow of time, establishing invariants that guarantee local greedy choices are globally optimal.

The 3 Spatial Overlap Archetypes

For any two intervals A = [sA, eA] and B = [sB, eB] with sA ≤ sB:

1. MUTUALLY DISJOINT (s_B > e_A):
   A: [=========]
   B:             [=======]
   Condition: s_B > e_A
   Action: No overlap. Interval A is permanently sealed and committed!

2. PARTIAL OVERLAP (s_B <= e_A < e_B):
   A: [=============]
   B:        [=============]
   Merged: [===============]
   Condition: s_B <= e_A and e_B > e_A
   Action: Merge into [s_A, max(e_A, e_B)] = [s_A, e_B].

3. COMPLETE ABSORPTION / SUBSET (s_B >= s_A and e_B <= e_A):
   A: [=====================]
   B:        [=======]
   Merged: [=====================]
   Condition: s_B <= e_A and e_B <= e_A
   Action: Interval B is swallowed. The cluster boundary remains [s_A, e_A].
Strategic Decision Matrix: Sort by Start vs Sort by End

The choice of sorting dimension completely dictates the algorithmic engine:

  • Sort by Start (s ↑): Used for Union & Clustering (Merge Intervals, Insert Interval, Meeting Room Concurrency, Line Sweep). Guarantees scurr ≥ sprev, so overlap simplifies to scurr ≤ eprev.
  • Sort by End (e ↑): Used for Greedy Activity Selection (Non-Overlapping Intervals, Burst Balloons). Earliest finish time leaves maximum possible free time for subsequent intervals, minimizing conflicts.
  • Sort by Start Ascending, End Descending (s ↑, e ↓): Used for Enclosure & Nesting (Remove Covered Intervals). Ensures that when start times tie, the widest covering interval is evaluated first.

Why it works: 3-Phase Linear Partition

Because the input list is already sorted and disjoint, intervals fall strictly into three consecutive chronological phases:

Existing: [1, 2]  [3, 5]  [6, 7]  [8, 10]  [12, 16],  New: [4, 8]

Phase 1 (Strictly Left): end < newStart (2 < 4)
  -> Append [1, 2] directly.

Phase 2 (Overlapping Cluster): start <= newEnd
  [3, 5] overlaps -> newInterval = [min(4, 3), max(8, 5)] = [3, 8]
  [6, 7] overlaps -> newInterval = [min(3, 6), max(8, 7)] = [3, 8]
  [8, 10] overlaps -> newInterval = [min(3, 8), max(8, 10)] = [3, 10]
  Append expanded cluster [3, 10].

Phase 3 (Strictly Right): start > newEnd (12 > 10)
  -> Append [12, 16] directly.

Interval List Intersections (LeetCode 986)

Use when: finding overlapping segments between two independent, pre-sorted lists of closed intervals.

Why it works: Two-Pointer Earliest-Finish Advance

Two intervals [s1, e1] and [s2, e2] intersect if max(s1, s2) ≤ min(e1, e2). The key optimization is pointer advancement: whichever interval finishes first (e1 < e2) cannot possibly intersect any future interval in the other list. Advancing its pointer in O(1) guarantees complete coverage in O(m + n) time.

def intervalIntersection(firstList: List[List[int]], secondList: List[List[int]]) -> List[List[int]]:    """LeetCode 986: Two-pointer dual sweep in O(m + n) time."""    result, i, j = [], 0, 0    m, n = len(firstList), len(secondList)    while i < m and j < n:        start1, end1 = firstList[i]        start2, end2 = secondList[j]        lo, hi = max(start1, start2), min(end1, end2)        if lo <= hi:            result.append([lo, hi])        if end1 < end2:            i += 1        else:            j += 1    return result

Why it works: Min-Heap Earliest-Free Room Simulation

Sort meetings by start time. A min-heap stores the finish times of all currently occupied rooms. For each new meeting starting at currStart:

  • The root of the heap roomHeap[0] represents the room that will be vacated earliest.

  • If roomHeap[0] > currStart, then NO active room has finished yet! A new room must be allocated.
  • The size of the heap dynamically tracks concurrent room utilization in O(n log n) time.

from collections import OrderedDict

class LRUCache:
    """
    Least Recently Used (LRU) Cache (LeetCode 146).
    All operations execute in strictly O(1) time complexity.
    """
    def __init__(self, capacity: int):
        self.capacity, self.cache = capacity, OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)        # Mark key as MRU (move to tail)
        return self.cache[key]

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self.cache.move_to_end(key)    # Mark key as MRU before updating value
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(False)      # Evict LRU key (head) in O(1)

Use when: 2D interval or envelope nesting where the primary dimension is sorted ascending and the secondary dimension MUST be sorted descending (or vice versa) to prevent false-positive overlap or collapse 2D search into 1D LIS (LC 354, LC 1288).

Why it works: Negation Inverts Secondary Ordering

In Russian Doll Envelopes ([w, h]), identical widths cannot nest. Sorting with key=lambda x: (x[0], -x[1]) places identical widths in strictly descending height order. When running 1D Longest Increasing Subsequence (LIS) on heights, an envelope with the same width cannot extend the sequence of another envelope with the same width, reducing O(n2) 2D DP to O(n log n)!

from bisect import bisect_left
from typing import List

def maxEnvelopes(envelopes: List[List[int]]) -> int:
    """
    Russian Doll Envelopes (LC 354 - Hard).
    Sort width ASCENDING, then height DESCENDING.
    Enables 1D O(n log n) Longest Increasing Subsequence.
    """
    if not envelopes:
        return 0

    # Width ASC, Height DESC to prevent same-width envelopes nesting
    envelopes.sort(key=lambda x: (x[0], -x[1]))

    tails = []
    for _, h in envelopes:
        idx = bisect_left(tails, h)
        if idx == len(tails):
            tails.append(h)
        else:
            tails[idx] = h

    return len(tails)

import re

def calculate(s: str) -> int:

    Basic Calculator II (LC 227 - Medium) using Regex Lexing.
    re.findall extracts numbers and operators cleanly in O(n) time.
    """
    tokens = re.findall(r'\d+|[+*/-]', s)
    stack, sign = [], "+"

    for tok in tokens:
        if tok.isdigit():
            val = int(tok)
            if sign == "+":   stack.append(val)
            elif sign == "-": stack.append(-val)
            elif sign == "*": stack.append(stack.pop() * val)
            elif sign == "/": stack.append(int(stack.pop() / val))
        else:
            sign = tok

    return sum(stack)

Restoring 2-Argument Comparator Semantics

Python 3 removed the legacy cmp parameter from sort(). functools.cmp_to_key(fn) converts a function returning −1, 0, 1 into a comparison key object with full O(n log n) correctness.

def largestNumber(nums: List[int]) -> str:
    """
    Largest Number (LC 179 - Medium).
    Pairwise comparator: compare str(a) + str(b) against str(b) + str(a).
    """
    def compare(a: str, b: str) -> int:
        if a + b > b + a:   return -1  # 'a' should precede 'b'
        elif a + b < b + a: return 1   # 'b' should precede 'a'
        return 0

# 1. THE 1-INDEXED (N + 1) RECURSIVE SEGMENT TREE (CP Standard, Clean Math)

class SegmentTreeOneIndexed:
    """
    1-Indexed (N + 1) Segment Tree:
    Root is 1; Left child = 2*i; Right child = 2*i + 1; Parent = i // 2.
    Self-contained in self.tree. Zero duplicate array storage.
    Time:  Build O(n) | Point Update O(log n) | Range Query O(log n)
    Space: O(4 * (n + 1))
    """
    def __init__(self, nums: List[int]):
        self.n, self.tree = len(nums), [0] * (4 * (len(nums) + 1))
        if self.n > 0:
            self.build(1, 1, self.n, nums)

    def build(self, node: int, left: int, right: int, nums: List[int]) -> None:
        if left == right:
            self.tree[node] = nums[left - 1]
            return
        mid = (left + right) // 2
        self.build(2 * node, left, mid, nums)
        self.build(2 * node + 1, mid + 1, right, nums)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    def update(self, node: int, left: int, right: int, idx: int, val: int) -> None:
        if left == right:
            self.tree[node] = val
            return
        mid = (left + right) // 2
        if idx <= mid:
            self.update(2 * node, left, mid, idx, val)
        else:
            self.update(2 * node + 1, mid + 1, right, idx, val)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    def query(self, node: int, left: int, right: int, qL: int, qR: int) -> int:
        if qR < left or qL > right:
            return 0
        if qL <= left and right <= qR:
            return self.tree[node]
        mid = (left + right) // 2
        return self.query(2 * node, left, mid, qL, qR) + self.query(2 * node + 1, mid + 1, right, qL, qR)

class ShortSegmentTree:
    """
    Iterative 2N Segment Tree: leaves at [n, 2n-1], parents at [1, n-1].
    Time:  Build O(n) | Point Update O(log n) | Range Query O(log n)
    Space: O(2n) flat contiguous array (no recursive overhead!)
    """
    def __init__(self, nums: List[int]):
        self.n = len(nums)
        self.tree = [0] * (2 * self.n)

        for i in range(self.n):
            self.tree[self.n + i] = nums[i]

        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.tree[2 * i] + self.tree[2 * i + 1]

    def update(self, idx: int, val: int) -> None:
        idx += self.n
        self.tree[idx] = val

        while idx > 1:
            idx //= 2
            self.tree[idx] = self.tree[2 * idx] + self.tree[2 * idx + 1]

    def query(self, left: int, right: int) -> int:
        res = 0
        left, right = left + self.n, right + self.n

        while left <= right:
            if left % 2 == 1:
                res += self.tree[left]
                left += 1

            if right % 2 == 0:
                res += self.tree[right]
                right -= 1

            left //= 2
            right //= 2

        return res

class FenwickTree:
    """
    Binary Indexed Tree (BIT) for prefix and range sums.
    Time:  Point Update O(log n) | Range Query O(log n)
    Space: O(n) exact memory with minimal constant factor
    """
    def __init__(self, n: int):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, idx: int, delta: int) -> None:
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & (-idx)

    def query(self, idx: int) -> int:
        total = 0

        while idx > 0:
            total += self.tree[idx]
            idx -= idx & (-idx)

        return total

    def rangeQuery(self, left: int, right: int) -> int:
        return self.query(right) - self.query(left - 1)

class SqrtDecomposition:
    """
    Square Root Decomposition: balances O(1) point updates with O(sqrt(n)) queries.
    Time:  Build O(n) | Point Update O(1) | Range Query O(sqrt(n))
    Space: O(n + sqrt(n))
    """
    def __init__(self, nums: List[int]):
        self.n, self.nums = len(nums), nums[:]
        self.blockSize = max(1, int(math.isqrt(self.n)))
        self.numBlocks = (self.n + self.blockSize - 1) // self.blockSize
        self.blocks = [0] * self.numBlocks

        for i in range(self.n):
            self.blocks[i // self.blockSize] += nums[i]

    def update(self, idx: int, val: int) -> None:
        blockIdx = idx // self.blockSize
        self.blocks[blockIdx] += val - self.nums[idx]
        self.nums[idx] = val

    def query(self, left: int, right: int) -> int:
        startBlock, endBlock = left // self.blockSize, right // self.blockSize

        if startBlock == endBlock:
            return sum(self.nums[left : right + 1])

        res = 0
        res += sum(self.nums[left : (startBlock + 1) * self.blockSize])

        for b in range(startBlock + 1, endBlock):
            res += self.blocks[b]

        res += sum(self.nums[endBlock * self.blockSize : right + 1])
        return res

Iterative 2N "Short Code" Segment Tree (Non-Recursive, High-Speed)

Use when: Maximum execution speed, zero recursion overhead, half the memory (2n instead of 4n), and concise competitive programming code are desired for point updates and range queries.

Why it works & Line-by-Line Short Code Breakdown

Top competitive programmers prefer the Iterative 2N Segment Tree ("Short Code") because it executes in flat contiguous memory with zero call-stack frames. Here is why the compact syntax works:

  • 1. The 2N Flat Memory Trick: The original array leaves are stored at indices [n, 2n − 1]. Original element nums[i] sits at tree[n + i]. Internal parent nodes occupy indices [1, n − 1], with root at index 1. Index 0 is unused. Total memory is strictly 2n!
  • 2. Binary Parity Rules: For any node at index i, its parent is i // 2. Its left child is 2 * i (always an EVEN index); its right child is 2 * i + 1 (always an ODD index).
  • 3. O(n) Bottom-Up Build: Populating from n − 1 down to 1 ensures children 2 * i and 2 * i + 1 are already initialized: tree[i] = tree[2 * i] + tree[2 * i + 1].
  • 4. O(log n) Point Update: idx += n; tree[idx] = val; while idx > 1: idx //= 2; tree[idx] = tree[2*idx] + tree[2*idx+1]. Directly mutates leaf and climbs ancestor path in O(log n) loop cycles.
  • 5. O(log n) Converging Query Invariant:
    • left, right = left + n, right + n
    • If left % 2 == 1: left is a right child. Its left sibling is outside our query range [left, right]! Therefore, its parent cannot be used. We must include tree[left] directly into the accumulator, and advance left += 1 to enter the next parent range!
    • If right % 2 == 0: right is a left child. Its right sibling is outside our query range! We must include tree[right] directly into the accumulator, and decrement right -= 1 before ascending!
    • Then ascend: left //= 2; right //= 2 until pointers cross (left > right).

from typing import List

class ShortSegmentTree:
    """
    Iterative 2N "Short Code" Segment Tree:
    High-performance, cache-friendly segment tree without recursion.

    Memory Layout for n = 4 (nums = [2, 1, 5, 3]):
    Index:  0    1     2     3     4     5     6     7
    Node:  [-] [0..3] [0..1] [2..3] [0]   [1]   [2]   [3]
    Value:  0    11     3     8     2     1     5     3
           Unused  <-- Parents -->  <--- Leaves (n..2n-1) --->

    Tree Invariants:
    - Leaves live at indices [n, 2n - 1] -> leaf for nums[i] is at n + i
    - Parent of node i is i // 2 (or i >> 1)
    - Left children always have EVEN index; Right children always have ODD index

    Time:  Build O(n) | Point Update O(log n) | Range Query O(log n)
    Space: Exactly 2n elements (half the memory of 4n recursive tree!)
    """
    def __init__(self, nums: List[int]):
        self.n = len(nums)
        self.tree = [0] * (2 * self.n)

        # 1. Populate leaves at indices [n, 2n - 1] in O(n)
        for i in range(self.n):
            self.tree[self.n + i] = nums[i]

        # 2. Build internal parents bottom-up from n - 1 down to 1 in O(n)
        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.tree[2 * i] + self.tree[2 * i + 1]

    def update(self, idx: int, val: int) -> None:
        """
        Point update: Climb ancestor chain in O(log n).
        Zero recursion, direct linear array jumps.
        """
        idx += self.n
        self.tree[idx] = val

        # Climb to root (node 1) updating parents
        while idx > 1:
            idx //= 2
            self.tree[idx] = self.tree[2 * idx] + self.tree[2 * idx + 1]

    def query(self, left: int, right: int) -> int:
        """
        Range query [left, right] inclusive in O(log n):
        - If left is odd: right child -> left sibling is outside range!
          Include tree[left] directly, then increment left to enter next parent.
        - If right is even: left child -> right sibling is outside range!
          Include tree[right] directly, then decrement right to enter next parent.
        - Divide both by 2 to ascend one level.
        """
        res = 0
        left, right = left + self.n, right + self.n

        while left <= right:
            if left % 2 == 1:
                res += self.tree[left]
                left += 1

            if right % 2 == 0:
                res += self.tree[right]
                right -= 1

            left //= 2
            right //= 2

        return res

1-Indexed (N + 1) Segment Tree with Lazy Propagation (Range Updates)

Use when: Modifying entire subarrays [qLeft, qRight] (e.g. adding +v or setting =v) and querying arbitrary ranges in O(log n) time without updating individual leaves.

Why it works: Deferred Subtree Propagation

Without lazy propagation, updating a range of size k requires visiting O(k) leaves, degrading to O(n) worst-case. Lazy propagation defers updates: when a tree node's range [left, right] is fully enclosed within query range [qLeft, qRight], we immediately apply tree[nodeIdx] += delta * (right - left + 1) and store lazy[nodeIdx] += delta.

Descendant children are only updated when a future query or update actually traverses through nodeIdx, executed via the pushDown(nodeIdx, left, right) routine. This preserves strictly O(log n) runtime for both range updates and range queries. 

from typing import List

class LazySegmentTreeOneIndexed:
    """
    1-Indexed (N + 1) Segment Tree with Lazy Propagation:
    Range Updates [qLeft, qRight] += delta and Range Queries in O(log n).

    Time:  Build O(n) | Range Update O(log n) | Range Query O(log n)
    Space: O(4 * (n + 1))
    """
    def __init__(self, nums: List[int]):
        self.n = len(nums)
        self.tree, self.lazy = [0] * (4 * (self.n + 1)), [0] * (4 * (self.n + 1))
        if self.n > 0:
            self.build(1, 1, self.n, nums)

    def build(self, node: int, left: int, right: int, nums: List[int]) -> None:
        if left == right:
            self.tree[node] = nums[left - 1]
            return
        mid = (left + right) // 2
        self.build(2 * node, left, mid, nums)
        self.build(2 * node + 1, mid + 1, right, nums)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    def pushDown(self, node: int, left: int, right: int) -> None:
        """Pushes pending lazy delta to children."""
        if self.lazy[node] == 0 or left == right:
            return
        mid, delta = (left + right) // 2, self.lazy[node]
        self.lazy[2 * node] += delta
        self.tree[2 * node] += delta * (mid - left + 1)
        self.lazy[2 * node + 1] += delta
        self.tree[2 * node + 1] += delta * (right - mid)
        self.lazy[node] = 0

    def updateRange(self, node: int, left: int, right: int, qLeft: int, qRight: int, delta: int) -> None:
        if qRight < left or qLeft > right:
            return
        if qLeft <= left and right <= qRight:
            self.tree[node] += delta * (right - left + 1)
            self.lazy[node] += delta
            return
        self.pushDown(node, left, right)
        mid = (left + right) // 2
        self.updateRange(2 * node, left, mid, qLeft, qRight, delta)
        self.updateRange(2 * node + 1, mid + 1, right, qLeft, qRight, delta)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    def queryRange(self, node: int, left: int, right: int, qLeft: int, qRight: int) -> int:
        if qRight < left or qLeft > right:
            return 0
        if qLeft <= left and right <= qRight:
            return self.tree[node]
        self.pushDown(node, left, right)
        mid = (left + right) // 2
        return self.queryRange(2 * node, left, mid, qLeft, qRight) + self.queryRange(2 * node + 1, mid + 1, right, qLeft, qRight)

from typing import Optional


class SegmentTreeNode:

    """Dynamic pointer node maintaining interval [leftBound, rightBound]."""

    def __init__(self, leftBound: int, rightBound: int):

        self.leftBound, self.rightBound = leftBound, rightBound

        self.val = 0

        self.lazy = 0

        self.hasLazy = False

        self.left: Optional[SegmentTreeNode] = None

        self.right: Optional[SegmentTreeNode] = None


class DynamicSegmentTree:

    """Pointer-Based Dynamic (Implicit) Segment Tree with Lazy Propagation.

    Dynamically allocates nodes on-demand. Enables coordinate universes up to
    10^9 without Memory Limit Exceeded (allocates at most O(Q log(MAX)) nodes).

    Tree Invariant & Dynamic Expansion Trace:
    Min Coordinate: 0  -----------------------------> Max Coordinate: 10^9
    Root: [0 .. 10^9]  (Allocated on start)
      ├── left:  [0 .. 5*10^8]       (Spawned dynamically on-demand during update)
      └── right: [5*10^8 + 1 .. 10^9] (Unallocated: None until accessed!)
    """
    def __init__(self, minCoord: int = 0, maxCoord: int = 10**9):

        self.root = SegmentTreeNode(minCoord, maxCoord)


    def _pushDown(self, node: SegmentTreeNode) -> None:

        if node.leftBound == node.rightBound:

            return


        mid = (node.leftBound + node.rightBound) // 2


        # Dynamically spawn child nodes on-demand (O(1) memory per spawn)

        if not node.left:

            node.left = SegmentTreeNode(node.leftBound, mid)

        if not node.right:

            node.right = SegmentTreeNode(mid + 1, node.rightBound)


        if node.hasLazy:

            # Propagate deferred delta to left child

            node.left.val += (node.left.rightBound - node.left.leftBound + 1) * node.lazy

            node.left.lazy += node.lazy

            node.left.hasLazy = True


            # Propagate deferred delta to right child

            node.right.val += (node.right.rightBound - node.right.leftBound + 1) * node.lazy

            node.right.lazy += node.lazy

            node.right.hasLazy = True


            # Clear parent lazy tag

            node.lazy = 0

            node.hasLazy = False


    def updateRange(self, node: SegmentTreeNode, qLeft: int, qRight: int, delta: int) -> None:

        """Adds delta to every element in contiguous range [qLeft, qRight]."""

        # Disjoint range: completely outside

        if qRight < node.leftBound or qLeft > node.rightBound:

            return


        # Complete overlap: current segment fully enclosed inside query window

        if qLeft <= node.leftBound and node.rightBound <= qRight:

            node.val += (node.rightBound - node.leftBound + 1) * delta

            node.lazy += delta

            node.hasLazy = True

            return


        # Partial overlap: spawn children and descend

        self._pushDown(node)

        self.updateRange(node.left, qLeft, qRight, delta)

        self.updateRange(node.right, qLeft, qRight, delta)


        # Pull updated sum from children

        node.val = (node.left.val if node.left else 0) + (node.right.val if node.right else 0)


    def queryRange(self, node: SegmentTreeNode, qLeft: int, qRight: int) -> int:

        """Returns the sum of all elements in range [qLeft, qRight]."""

        if not node or qRight < node.leftBound or qLeft > node.rightBound:

            return 0


        if qLeft <= node.leftBound and node.rightBound <= qRight:

            return node.val


        self._pushDown(node)

        leftSum = self.queryRange(node.left, qLeft, qRight)

        rightSum = self.queryRange(node.right, qLeft, qRight)


        return leftSum + rightSum

class FenwickTree:
    """
    Binary Indexed Tree (BIT / Fenwick Tree):
    Maintains prefix sums with O(log n) updates and queries in strictly O(n) space.

    lowbit Invariant: lowbit(x) = x & (-x)
    Tree Node x covers length lowbit(x), specifically range [x - lowbit(x) + 1, x].

    Time:  Point Update O(log n) | Prefix Query O(log n) | Range Query O(log n)
    Space: O(n) exact memory (no overhead!)
    """
    def __init__(self, n: int):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, idx: int, delta: int) -> None:
        """
        Add delta to element at 1-based index idx.
        Climbs up the tree by adding the lowest set bit.
        """
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & (-idx)

    def query(self, idx: int) -> int:
        """
        Compute prefix sum nums[1..idx].
        Descends down the tree by stripping the lowest set bit.
        """
        total = 0

        while idx > 0:
            total += self.tree[idx]
            idx -= idx & (-idx)

        return total

    def rangeQuery(self, left: int, right: int) -> int:
        """Inclusive sum over range [left, right] (1-based indices)."""
        return self.query(right) - self.query(left - 1)

class FenwickRangeUpdateRangeQuery:

    """Two-BIT Engine: Supports BOTH Range Updates and Range Queries in O(log n).

    Maintains two BITs over the difference array D[i] = A[i] - A[i-1]:
    - bit1 tracks: D[i]
    - bit2 tracks: D[i] * (i - 1)

    Mathematical Derivation & Invariant:
    A[i] = sum_{k=1..i} D[k]
    prefixSum(i) = sum_{j=1..i} A[j]
                 = sum_{j=1..i} sum_{k=1..j} D[k]
                 = sum_{k=1..i} D[k] * (i - k + 1)
                 = (i + 1) * sum_{k=1..i} D[k] - sum_{k=1..i} (D[k] * k)
                 = i * sum D[k] - sum (D[k] * (k - 1))
                 = i * query(bit1, i) - query(bit2, i)
    """
    def __init__(self, n: int):

        self.n = n

        self.bit1 = [0] * (n + 1)

        self.bit2 = [0] * (n + 1)


    def _add(self, bit: List[int], idx: int, delta: int) -> None:

        """Adds delta to target BIT at index idx (1-based)."""

        while idx <= self.n:

            bit[idx] += delta

            idx += idx & (-idx)


    def _query(self, bit: List[int], idx: int) -> int:

        """Returns prefix sum of target BIT up to index idx (1-based)."""

        total = 0

        while idx > 0:

            total += bit[idx]

            idx -= idx & (-idx)

        return total


    def updateRange(self, left: int, right: int, delta: int) -> None:

        """Adds delta to all elements in range [left, right] (1-based)."""

        # Maintain bit1 (stores D[k])

        self._add(self.bit1, left, delta)

        self._add(self.bit1, right + 1, -delta)


        # Maintain bit2 (stores D[k] * (k - 1))

        self._add(self.bit2, left, delta * (left - 1))

        self._add(self.bit2, right + 1, -delta * right)


    def prefixSum(self, idx: int) -> int:

        """Computes prefix sum of array from index 1 to idx in O(log n)."""

        return idx * self._query(self.bit1, idx) - self._query(self.bit2, idx)


    def queryRange(self, left: int, right: int) -> int:

        """Returns sum of elements in range [left, right] in O(log n)."""

        return self.prefixSum(right) - self.prefixSum(left - 1)

Coordinate Compression & Dynamic Inversion Counting

Use when: Counting inversions, finding count of smaller numbers to the right/left, or dynamic order statistics on unconstrained numeric domains.

Why it works: Right-to-Left Frequency Sweeping

When input values can be negative or large (e.g., up to 109), map them to compact ranks [1, U] via rankMap = {val: rank + 1 for rank, val in enumerate(sorted(set(nums)))} in O(n log n). Traversing from right to left, every element query bit.query(currRank - 1) counts all elements already inserted to its right with strictly smaller values in O(log n) time. 

from typing import List

def countSmallerAfterSelf(nums: List[int]) -> List[int]:
    """
    LeetCode 315: Count of Smaller Numbers After Self.
    Traverse right to left with Coordinate Compression + Fenwick Frequency Tree.

    Time:  O(n log n)
    Space: O(n)
    """
    if not nums:
        return []

    # 1. Coordinate compression to map unique values to ranks [1, U]
    sortedVals = sorted(set(nums))
    rankMap = {val: rank + 1 for rank, val in enumerate(sortedVals)}
    maxRank, n = len(sortedVals), len(nums)

    bit = FenwickTree(maxRank)
    res = [0] * n

    # 2. Iterate backwards from right to left
    for i in range(n - 1, -1, -1):
        currRank = rankMap[nums[i]]

        # Count elements already placed with strictly smaller rank [1..currRank - 1]
        res[i] = bit.query(currRank - 1)

        # Insert current element into BIT frequency tree
        bit.update(currRank, 1)

    return res

from typing import List
import math

class SqrtDecomposition:
    """
    Square Root Decomposition:
    Partitions array into blocks of size B = ceil(sqrt(n)).

    Time:  Point Update O(1) | Range Query O(sqrt(n)) | Build O(n)
    Space: O(n) array storage + O(sqrt(n)) block summaries
    """
    def __init__(self, nums: List[int]):
        self.n, self.nums = len(nums), nums[:]
        self.blockSize = max(1, int(math.isqrt(self.n)))
        self.numBlocks = (self.n + self.blockSize - 1) // self.blockSize
        self.blocks = [0] * self.numBlocks

        for i in range(self.n):
            self.blocks[i // self.blockSize] += nums[i]

    def update(self, idx: int, val: int) -> None:
        """O(1) Point Update."""
        blockIdx = idx // self.blockSize
        self.blocks[blockIdx] += val - self.nums[idx]
        self.nums[idx] = val

    def query(self, left: int, right: int) -> int:
        """
        O(sqrt(n)) Range Query [left, right] inclusive:
        Aggregates partial left block, full middle blocks, and partial right block.
        """
        startBlock, endBlock = left // self.blockSize, right // self.blockSize

        if startBlock == endBlock:
            return sum(self.nums[left : right + 1])

        res = 0
        # 1. Partial head block
        res += sum(self.nums[left : (startBlock + 1) * self.blockSize])

        # 2. Complete middle blocks in O(1) each
        for b in range(startBlock + 1, endBlock):
            res += self.blocks[b]

        # 3. Partial tail block
        res += sum(self.nums[endBlock * self.blockSize : right + 1])

        return res

Range Updates [L, R] += Δ AND Range Queries [L, R] with Lazy Block Tags in O(√n)

Use when: Both range updates and range queries are required, but you prefer a simple, flat square-root array structure over complex pointer or segment tree implementations.

Why it works: Partial Boundary Mutation + Full Block Deferred Tags

When an update spans multiple blocks, we divide the range [L, R] into three phases:

  • 1. Left Partial Block: Elements from L to end of block startBlock. Add Δ directly to nums[i] and adjust blockSums[startBlock] += Δ in O(√n).
  • 2. Middle Full Blocks: Blocks strictly between startBlock and endBlock. Apply deferred tag blockLazy[b] += Δ and update blockSums[b] += Δ × blockSize in O(1) per block.
  • 3. Right Partial Block: Elements from start of block endBlock to R. Add Δ directly to nums[i] and adjust blockSums[endBlock] += Δ in O(√n).

Phase 1 Left Partial: mutate nums[L..end] in O(√n)
Phase 2 Middle Blocks: blockLazy[b] += Δ in O(1) per block
Phase 3 Right Partial: mutate nums[start..R] in O(√n) 
from typing import List


class SqrtDecompositionLazy:

    """SQRT Decomposition supporting Range Updates and Range Queries in O(sqrt(n)).

    Maintains block sums and deferred lazy addition tags on blocks of size B = ceil(sqrt(n)).
    """
    def __init__(self, nums: List[int]):

        self.n = len(nums)

        self.nums = nums[:]

        self.blockSize = max(1, int(self.n ** 0.5))

        self.numBlocks = (self.n + self.blockSize - 1) // self.blockSize

        self.blockSums = [0] * self.numBlocks

        self.blockLazy = [0] * self.numBlocks


        # Precompute initial block sums in O(n)

        for i, val in enumerate(self.nums):

            self.blockSums[i // self.blockSize] += val


    def updateRange(self, left: int, right: int, delta: int) -> None:

        """Adds delta to all elements in range [left, right] in O(sqrt(n))."""

        startBlock, endBlock = left // self.blockSize, right // self.blockSize


        # Case 1: Range strictly inside a single block

        if startBlock == endBlock:

            for i in range(left, right + 1):

                self.nums[i] += delta

                self.blockSums[startBlock] += delta

            return


        # Case 2: Multi-block range

        # Step A: Left partial block

        for i in range(left, (startBlock + 1) * self.blockSize):

            self.nums[i] += delta

            self.blockSums[startBlock] += delta


        # Step B: Full middle blocks (apply O(1) lazy tag per block)

        for b in range(startBlock + 1, endBlock):

            self.blockLazy[b] += delta

            self.blockSums[b] += delta * self.blockSize


        # Step C: Right partial block

        for i in range(endBlock * self.blockSize, right + 1):

            self.nums[i] += delta

            self.blockSums[endBlock] += delta


    def queryRange(self, left: int, right: int) -> int:

        """Returns sum of elements in range [left, right] in O(sqrt(n))."""

        startBlock, endBlock = left // self.blockSize, right // self.blockSize

        total = 0


        # Case 1: Single block query

        if startBlock == endBlock:

            for i in range(left, right + 1):

                total += self.nums[i] + self.blockLazy[startBlock]

            return total


        # Case 2: Multi-block query

        # Step A: Left partial block

        for i in range(left, (startBlock + 1) * self.blockSize):

            total += self.nums[i] + self.blockLazy[startBlock]


        # Step B: Full middle blocks (O(1) read from precomputed blockSums)

        for b in range(startBlock + 1, endBlock):

            total += self.blockSums[b]


        # Step C: Right partial block

        for i in range(endBlock * self.blockSize, right + 1):

            total += self.nums[i] + self.blockLazy[endBlock]


        return total

Mo's Algorithm (Offline Range Query Reordering)

Use when: Answering Q offline range queries where maintaining a state over [L, R] takes O(1) per pointer shift +-1.

Why it works: Serpentine Parity Sorting Trick

If all Q queries are known in advance, group queries by q.left // B, and sort q.right in alternating directions: ascending on even blocks, descending on odd blocks. This eliminates pointer whip-back, bounding total window adjustments to O((N + Q)√N). 

from typing import List
import math

class MosAlgorithm:
    """
    Mo's Algorithm: Offline Range Query Optimization in O((N + Q) * sqrt(N)).
    Reorders queries so two pointers (currL, currR) move minimal total distance.
    """

    def __init__(self, nums: List[int]):
        self.nums = nums
        self.n = len(nums)
        self.blockSize = max(1, int(math.isqrt(self.n)))

    def solveQueries(self, rawQueries: List[List[int]]) -> List[int]:
        queries = [(q[0], q[1], idx) for idx, q in enumerate(rawQueries)]

        # Mo's Serpentine Sort
        queries.sort(key=lambda q: (
            q[0] // self.blockSize,
            q[1] if (q[0] // self.blockSize) % 2 == 0 else -q[1]
        ))

        res = [0] * len(queries)
        currL, currR, currSum = 0, -1, 0

        for left, right, originalIdx in queries:
            while currR < right:
                currR += 1
                currSum += self.nums[currR]

            while currL > left:
                currL -= 1
                currSum += self.nums[currL]

            while currR > right:
                currSum -= self.nums[currR]
                currR -= 1

            while currL < left:
                currSum -= self.nums[currL]
                currL += 1

            res[originalIdx] = currSum

        return res

Static RMQ via Overlapping Dyadic Intervals

Use when: The array is immutable (zero updates) and you need ultra-fast O(1) Range Minimum or Range Maximum queries across up to 10⁶ queries.

Why it works: Idempotency & Dyadic Doubling Invariant

An algebraic operation ☆ is idempotent if x ☆ x = x. For example: min(5, 5) = 5, gcd(12, 12) = 12, 14 & 14 = 14. Because duplicating elements has zero effect on the result, we do not need disjoint partitions like Segment Trees. Any range [L, R] of length k = R − L + 1 is completely covered by two overlapping blocks of size 2ʲ, where j = ⌊log&sub2;(k)⌋:
Block 1: [L, L + 2ʲ − 1]  •  Block 2: [R − 2ʲ + 1, R]

from typing import List, Callable
import math

class SparseTable:
    """
    Sparse Table Range Minimum Query (RMQ) Engine.
    Builds in O(n log n) time and space.
    Answers static queries in strictly O(1) time for idempotent operations (min, max, gcd).
    """
    def __init__(self, nums: List[int], op: Callable[[int, int], int] = min) -> None:
        if not nums:
            self.st, self.op = [], op
            return

        n, self.op = len(nums), op
        k = n.bit_length()
        self.st = [[0] * n for _ in range(k)]
        self.st[0] = list(nums)

        # Tabulate interval lengths of powers of 2
        for j in range(1, k):
            step = 1 << (j - 1)
            for i in range(n - (1 << j) + 1):
                self.st[j][i] = op(self.st[j - 1][i], self.st[j - 1][i + step])

    def query(self, left: int, right: int) -> int:
        """
        O(1) Idempotent Range Query on [left .. right].
        Uses two overlapping blocks of size 2^j to cover the range.
        Because op(x, x) == x, overlapping elements do not distort the result.
        """
        j = (right - left + 1).bit_length() - 1
        return self.op(self.st[j][left], self.st[j][right - (1 << j) + 1])

    def queryDisjointSum(self, left: int, right: int) -> int:
        """
        O(log n) Non-Idempotent Range Sum on [left .. right].
        Decomposes range into disjoint dyadic binary powers of 2.
        """
        res, currIdx = 0, left

        for j in range(len(self.st) - 1, -1, -1):
            if currIdx + (1 << j) - 1 <= right:
                res += self.st[j][currIdx]
                currIdx += 1 << j

        return res

Range GCD & Bitwise Monoids (AND / OR)

Use when: Range Greatest Common Divisor or bitwise operations (&, |) over static arrays where queries must execute in O(1) table lookups.

Why it works: Idempotence of GCD and Bitwise Logic

Because gcd(a, a) = a, overlapping segments do not alter the greatest common divisor. The exact same two-block query engine applies: j = (right - left + 1).bit_length() - 1, then math.gcd(st[j][left], st[j][right - (1 << j) + 1]). 

from typing import List
import math

class SparseTableGCD:
    """
    Sparse Table for static Range Greatest Common Divisor (GCD).
    GCD is associative and idempotent: gcd(a, a) == a.
    Answers range GCD in strictly O(1) table lookups (excluding gcd math).
    """
    def __init__(self, nums: List[int]) -> None:
        n = len(nums)
        k = n.bit_length()
        self.st = [[0] * n for _ in range(k)]
        self.st[0] = list(nums)

        for j in range(1, k):
            step = 1 << (j - 1)
            for i in range(n - (1 << j) + 1):
                self.st[j][i] = math.gcd(self.st[j - 1][i], self.st[j - 1][i + step])

    def queryGCD(self, left: int, right: int) -> int:
        """Answers range GCD on [left .. right] in O(1) table access."""
        j = (right - left + 1).bit_length() - 1
        return math.gcd(self.st[j][left], self.st[j][right - (1 << j) + 1])

Disjoint Binary Decomposition for Non-Idempotent Sums (O(log n))

Use when: Evaluating non-idempotent operations (such as Range Sum) on a Sparse Table without double-counting overlapping elements.

Why it works: Greedy Binary Partitioning

Addition is NOT idempotent (x + x ≠ x). To compute range sums using a Sparse Table without double-counting, we decompose [left .. right] into disjoint binary powers of 2 (similar to Fenwick tree decomposition). We jump from left to right using the largest power of 2 that fits without exceeding right. Takes O(log n) additions and guarantees zero overlap!
