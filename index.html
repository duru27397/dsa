Core Principles

Dynamic Programming Decision Framework

1. When to Use DP vs Greedy

Prerequisites: Overlapping subproblems + optimal substructure.

Two Spotting Signals

• Target Question: Asks for Min/Max, Count of Ways, Longest/Shortest, or Feasibility.
• Decision Dependency: Earlier choices constrain future options (e.g. House Robber: robbing house i forbids house i+1). If greedy choice isn't guaranteed optimal, use DP.

2. The 3-Step Framework

Method: State → Transition → Base Cases.

Step-by-Step Formulation

• 1. State Definition: Define dp(i, ...) using only relevant variables (e.g. current stair step).
• 2. Recurrence Relation: Express dp[i] in terms of previous states: dp[i] = dp[i-1] + dp[i-2].
• 3. Base Cases: Smallest states solvable directly (e.g. dp[1] = 1, dp[2] = 2).

3. Top-Down vs Bottom-Up

Top-Down: Recursion + Memo.
Bottom-Up: Iteration + Tabulation.

Trade-offs & Selection

• Top-Down (@cache): Intuitive to write; subproblem order doesn't matter; computes only reachable states.
• Bottom-Up (Iteration): Faster (zero call stack overhead); enables O(1) space optimization by tracking only last k states.

The Two Fundamental Engines

Architectural Models: Volume vs. Measurement

Architecture 1: The Combinatorics Basket (Addition)

Use when: "How many ways?", "Total combinations", "Count valid paths".

The Goal: Total Volume

You are not looking for the "best" path—you are finding every path. Never use max() or min(), and never add 1 +. Simply sum the universes together.

# Template 1A: 0/1 Choices (Explicit Take / Skip)@cachedef countWays(index: int, target: int) -> int:    """The Combinatorics Basket: Count all valid routes to target."""    if target == 0:        return 1                    # Valid path reached    if index == n or target < 0:        return 0                    # Dead end: budget or items exhausted    take = countWays(index + 1, target - nums[index])    skip = countWays(index + 1, target)    return take + skip                  # Combine volumes without max/min# Template 1B: Shopping Menu (1D Jump Loop)@cachedef countJumps(index: int) -> int:    """The Combinatorics Basket: Sum all reachable jump choices."""    totalWays = 0    for nextIndex in range(index, n):        if isValid(nextIndex):            totalWays += countJumps(nextIndex + 1)    return totalWays

Architecture 2: The Optimization Ruler (Min / Max)

Use when: "Minimum days", "Maximum profit", "Longest length", "Shortest path".

The Goal: Measurement

Taking a step costs something (a coin, a step, time). You add the cost (e.g. 1 + or value +) to recursive calls and measure the outcomes against each other using min or max.

# Template 2A: 0/1 Choices (Explicit Take / Skip)@cachedef maxProfit(index: int, capacity: int) -> int:    """The Optimization Ruler: Maximize value subject to capacity budget."""    if capacity == 0 or index == n:        return 0    skip = maxProfit(index + 1, capacity)    take = 0    if capacity >= weight[index]:        take = value[index] + maxProfit(index + 1, capacity - weight[index])    return max(take, skip)               # Compare and keep the best# Template 2B: Shopping Menu (1D Optimization Loop)@cachedef minCoins(target: int) -> float:    """The Optimization Ruler: Minimize cost across menu choices."""    if target == 0:        return 0    if target < 0:        return float('inf')    bestCost = float('inf')    for coin in coins:        bestCost = min(bestCost, 1 + minCoins(target - coin))    return bestCost

Greedy vs DP Strategy

When Can DP Be Compressed into Greedy?

The Danger of "Always": The Jump Game Trap

Myth: "If there are no capacity/weight limits, I can always use Greedy."

Why Pure Greedy Fails on Jump Game II

Consider nums = [2, 3, 1, 1, 4]:
• At index 0, value is 2. A greedy choice says: "Jump the maximum (2 steps) to index 2!"
• But index 2 holds a 1 (requiring 1 step then 1 step → 3 jumps total).
• If you jumped 1 step to index 1 (value 3), you could leap directly to the end in 2 jumps!
Lesson: The immediate local greedy choice locked you out of a better geometric position.

The Architect's 3-Step Greedy Checklist

Goal: Prove whether an O(n log n) Greedy loop can replace an O(n²) DP multiverse.

Checklist (Must Pass All 3)

1. Is the problem asking for a Global Extreme?
Must ask for Min, Max, Longest, or Shortest. If it asks for "Number of ways", Greedy is impossible → use DP.

2. Is there a strict Mathematical Tipping Point?
Can you write an exact condition where an option is mathematically proven bad (e.g. negativeDish > sumOfPositives)? If yes, an if break replaces branching.

3. Does Sorting Organize the Tipping Point?
Greedy almost always requires sorted input so all worse choices are clustered. If the problem forbids reordering (e.g. LIS), simple Greedy fails.

Array & String Physics

Subarray vs. Subsequence Invariants

1. Subarray / Substring (Contiguous)

The Rule: No gaps allowed. Elements must sit strictly adjacent.

The Physics: Extend or Restart

The worker cannot skip an item! If an item is refused, the current streak dies permanently.
• Engine: Either extend the streak with the current element, or restart a brand new streak from scratch (e.g. Kadane's dp[i] = max(x, dp[i-1] + x), Maximum Product Subarray).

2. Subsequence (Non-Contiguous)

The Rule: Gaps are legally allowed. Relative order is preserved.

The Physics: Take or Skip

The worker evaluates an item. If skipped, the historical streak stays alive in the pocket as they advance to the next index.
• Explicit Take/Skip: take = ..., skip = dp(index + 1) (0/1 Knapsack, LCS).
• Implicit Jump Loop: for nextIdx in range(currIdx + 1, n): take = 1 + dp(nextIdx). Jumping directly over elements is the skip (LIS)!

📈 1D State Transitions

Summarize the subproblem into minimal state variables and advance through transitions without recomputing overlapping branches.

State + transition

Use when: the answer at position i depends on a small, fixed amount of earlier work.

Why it works

The state summarizes every relevant way to reach the current position. The transition considers the allowed previous moves exactly once.

def rob(nums: List[int]) -> int:    """1D DP: Rolling O(1) space state transition (House Robber)."""    prev2, prev1 = 0, 0  # prev2 = dp[i-2], prev1 = dp[i-1]    for value in nums:        # Choose max between skipping current (prev1) or taking current (prev2 + value)        prev2, prev1 = prev1, max(prev1, prev2 + value)    return prev1

📈 Knapsack & Decisions

Decide whether to include or exclude an item, updating optimal capacity states or reachability masks with bounded (reverse) or unbounded (forward) loops.

0/1 Knapsack (Bounded: Single-Use, Reverse Loop)

Use when: Each item can be picked at most once (0 or 1). Target sum, subset sum partition, or exact capacity budget.

Why it works & The Reverse Loop Invariant

In 1D space-optimized DP, we loop capacity in reverse (from capacity down to weight). This ensures dp[cap - weight] comes from the previous item's evaluation, preventing the same item from being counted multiple times.

Reverse Capacity Traversal (Preventing Double-Counting):
Capacity: [0, 1, 2, 3, 4, 5]
Item weight = 2, val = 3
Iterate cap: 5 -> 4 -> 3 -> 2
dp[5] = max(dp[5], dp[3] + 3)  <-- dp[3] still holds OLD item state!
If we went forward: dp[2] updated -> dp[4] uses new dp[2] (DUPLICATE USE!)
def canPartition(nums: List[int]) -> bool:    """0/1 Knapsack: Bounded partition into equal sum subsets."""    totalSum = sum(nums)    if totalSum % 2 != 0:        return False    target = totalSum // 2    dp = [False] * (target + 1)    dp[0] = True  # Base case: sum 0 is always possible    for num in nums:        # Reverse loop: stop at num to prevent reusing current num        for cap in range(target, num - 1, -1):            dp[cap] = dp[cap] or dp[cap - num]    return dp[target]

Unbounded Knapsack (Infinite Supply, Forward Loop)

Use when: Items can be reused an unlimited number of times (e.g. Coin Change, Rod Cutting).

Why it works & The Forward Loop Invariant

In 1D space-optimized DP, we loop capacity forward (from coin up to amount). This deliberately allows dp[cap - coin] to use the current iteration's results, letting a coin be chosen again and again.

Forward Capacity Traversal (Allowing Unlimited Reuse):
Coin = 2:
cap = 2: dp[2] = min(inf, dp[0] + 1) = 1
cap = 4: dp[4] = min(inf, dp[2] + 1) = 2  <-- Uses dp[2] from SAME coin pass!
cap = 6: dp[6] = min(inf, dp[4] + 1) = 3  <-- Reused 3 times!
def coinChange(coins: List[int], amount: int) -> int:    """Unbounded Knapsack: Min coins with unlimited supply."""    dp = [float('inf')] * (amount + 1)    dp[0] = 0    for coin in coins:        # Forward loop: allows reusing the same coin multiple times        for cap in range(coin, amount + 1):            if dp[cap - coin] + 1 < dp[cap]:                dp[cap] = dp[cap - coin] + 1    return dp[amount] if dp[amount] != float('inf') else -1

Word Break (Prefix Reachability & Dictionary Matching)

Use when: A string must be segmented into valid dictionary words or valid variable-length tokens.

Why it works & Prefix Invariant

dp[i] is True if prefix s[:i] can be segmented into words. For each position i, scan valid earlier cut points j; if dp[j] is True and s[j:i] is in the word set, then dp[i] = True.

String: "leetcode", Words: ["leet", "code"]
dp: [T, F, F, F, F, F, F, F, F]
i=4: j=0 -> dp[0] is T, s[0:4] == "leet" (valid) -> dp[4] = T
i=8: j=4 -> dp[4] is T, s[4:8] == "code" (valid) -> dp[8] = T (Result)
def wordBreak(s: str, wordDict: List[str]) -> bool:    """Prefix Reachability: Segment string into dictionary words."""    wordSet, n = set(wordDict), len(s)    dp = [False] * (n + 1)    dp[0] = True  # Empty prefix is always reachable    for i in range(1, n + 1):        for j in range(i):            if dp[j] and s[j:i] in wordSet:                dp[i] = True                break  # Once reachable, skip remaining cut points    return dp[n]

Longest Increasing Subsequence (O(n²) Jump Loop)

Use when: Finding longest subsequence under custom transition rules where binary search is not applicable, or when n ≤ 2500.

Why it works & Subsequence Jump Physics

In subsequence problems, skipping elements does not break continuity. The inner loop for j in range(i) acts as an implicit jump: checking whether nums[j] < nums[i] allows nums[i] to extend any valid previous subsequence ending at j, effectively skipping all elements between j and i.

Jump Loop Invariant:
nums = [10, 9, 2, 5, 3, 7]
dp   = [ 1, 1, 1, 1, 1, 1]  (each element starts with length 1)

i=3 (val=5): checks j=0(10), j=1(9), j=2(2 < 5) -> dp[3] = max(1, dp[2]+1) = 2
i=5 (val=7): checks j=2(2 < 7 -> 2), j=3(5 < 7 -> 3), j=4(3 < 7 -> 3) -> dp[5] = 3
Max LIS = max(dp) = 3 (subsequence [2, 5, 7] or [2, 3, 7])
def lengthOfLISQuadratic(nums: List[int]) -> int:    """    LIS O(n^2): Quadratic jump loop checking all valid predecessors.    dp[i] = length of longest increasing subsequence ending at index i.    """    if not nums:        return 0    n, dp = len(nums), [1] * len(nums)    for i in range(n):        # Jump loop: jumping directly from j to i implicitly skips intermediate elements        for j in range(i):            if nums[j] < nums[i]:                dp[i] = max(dp[i], dp[j] + 1)    return max(dp)

Longest Increasing Subsequence (O(n log n) Patience Sorting)

Use when: n up to 10⁵, requiring optimal LIS length (or 2D envelope sorting problems).

Why it works & The Patience Sorting Invariant

tails[k] stores the smallest tail of all increasing subsequences of length k + 1. Since tails is strictly increasing, we can use binary search (bisectLeft). Replacing a tail with a smaller number doesn't change the max length, but lowers the threshold for future numbers to extend the sequence.

Patience Sorting / Minimal Tail Invariant:
nums = [10, 9, 2, 5, 3, 7, 101, 18]

num = 10 -> tails: [10]
num = 9  -> 9 < 10, replace -> tails: [9]
num = 2  -> 2 < 9,  replace -> tails: [2]
num = 5  -> 5 > 2,  append  -> tails: [2, 5]
num = 3  -> 3 < 5,  replace -> tails: [2, 3]   <-- Lower tail for len 2!
num = 7  -> 7 > 3,  append  -> tails: [2, 3, 7]
num = 101-> 101 > 7,append  -> tails: [2, 3, 7, 101]
num = 18 -> 18 < 101,replace-> tails: [2, 3, 7, 18]  <-- Lower tail for len 4!

Result: len(tails) = 4
from bisect import bisect_left as bisectLeftdef lengthOfLIS(nums: List[int]) -> int:    """    LIS O(n log n): Patience sorting with binary search.    tails[k] = smallest ending value of all increasing subsequences of length k+1.    """    tails = []    for num in nums:        idx = bisectLeft(tails, num)        if idx == len(tails):            tails.append(num)  # num extends the longest subsequence found so far        else:            tails[idx] = num   # Greedily lower the tail for subsequences of length idx+1    return len(tails)

Decode Ways (String States & Lookahead)

Use when: Parsing digit strings with variable token lengths (1-digit: '1'-'9', 2-digit: '10'-'26').

Why it works & The Combinatorics Basket

This is an addition engine problem: count total valid decodings. At each index, we sum the valid single-digit transition (from prev1) and the valid two-digit transition (from prev2), maintaining O(1) rolling state.

Decode Ways Transitions:
s = "226"
i=0 ('2'): ways = 1 (prev1=1, prev2=1)
i=1 ('2'):
  - 1-digit '2' is valid -> adds prev1 (1)
  - 2-digit '22' is valid -> adds prev2 (1) -> curr = 2 (prev1=2, prev2=1)
i=2 ('6'):
  - 1-digit '6' is valid -> adds prev1 (2)
  - 2-digit '26' is valid -> adds prev2 (1) -> curr = 3 (prev1=3)
Total Ways = 3 ("BZ", "VF", "BBF")
def numDecodings(s: str) -> int:    """Decode Ways: Count total valid decodings with O(1) rolling space."""    if not s or s[0] == '0':        return 0    # prev2 = dp[i-2], prev1 = dp[i-1]    prev2, prev1 = 1, 1    for i in range(1, len(s)):        curr = 0        # 1-digit decode (valid if s[i] != '0')        if s[i] != '0':            curr += prev1        # 2-digit decode (valid if '10' <= s[i-1:i+1] <= '26')        twoDigit = int(s[i - 1 : i + 1])        if 10 <= twoDigit <= 26:            curr += prev2        prev2, prev1 = prev1, curr    return prev1

🥞 Monotonic Queue & Deque

Sliding window optimum with purge

Why it works & Visual Trace

If element A is older than B (idx_A < idx_B and val_A ≤ val_B), A can never be the maximum in any current or future window containing B. Popping dominated back elements keeps the deque strictly decreasing; the front always yields the window maximum in O(1)!

def maxSlidingWindow(nums: List[int], k: int) -> List[int]:    """    Monotonic deque: sliding window maximum in O(1) amortized.    Maintains indices of decreasing values within current window.    """    q, res = deque(), []    for i, x in enumerate(nums):        # Drop elements falling outside the sliding window        while q and q[0] < i - k + 1:            q.popleft()        # Drop dominated smaller elements from the back        while q and nums[q[-1]] <= x:            q.pop()        q.append(i)        if i >= k - 1:            res.append(nums[q[0]])  # Front is window maximum    return res

🔗 Union-Find (DSU): Overview & Blueprint

Maintain dynamic equivalence classes, detect cycles, and track connected components in near-constant time O(α(n)) using Path Compression and Union by Rank.

Core Mechanics & Optimizations

How Nodes, Path Compression & Rank Work

1. Disjoint Forest Representation

The Concept: Elements are nodes in an up-tree directed forest.

Self-Root Representation

Every node i is initialized pointing to itself: parent[i] = i. A component's representative (root) is the unique node where parent[root] == root. Merging sets simply attaches one root under another.

2. Path Compression Optimization

The Invariant: Why re-climb a tall tree? Flatten paths during find.

Recursive Flattening

During find(x), as recursion unwinds, every visited ancestor updates its parent pointer directly to the root: parent[x] = find(parent[x]). Subsequent queries run in O(1) depth.

Theoretical Foundation

What is the Inverse Ackermann Function α(n)?

1. The Ackermann Function A(m, n)

Definition: A hyper-exponential mathematical function that grows faster than any tower of powers.

Astronomical Explosion

• A(1, n) = n + 2 (Linear)
• A(2, n) = 2n + 3 (Multiplication)
• A(3, n) = 2^(n+3) - 3 (Exponentiation)
• A(4, n) = 2^(2^(2^...)) - 3 (Tower of 2s of height n + 3)
Specifically, A(4, 2) = 2^65536 - 3, a number with ≈ 19,729 decimal digits!

2. The Inverse α(n) Definition

Definition: The inverse α(n) is the smallest k such that A(k, k) ≥ n.

Why α(n) ≤ 4 in Real Life

Because A(4, 4) is so unimaginably colossal (vastly exceeding 10⁸⁰, the total number of atoms in the observable universe):
• For all n ≤ 10⁸⁰, α(n) ≤ 4.
• In any practical computer program, α(n) will never exceed 4.
• Thus, O(α(n)) is mathematically amortized but practically identical to O(1).

3. Optimization Synergies

Synergy: Why both Path Compression and Union by Rank are required.

Complexity Breakdown

• Neither: O(n) per operation (degenerates into linked list).
• Rank Only: O(log n) strictly bounded tree height.
• Path Compression Only: O(log n) amortized.
• Both Combined: O(α(n)) amortized near-constant time.

Architectural Comparison

Union-Find vs. BFS vs. DFS: When & Why

1. Dynamic Connectivity (UF Superpower)

The Core Advantage: Edge additions arrive dynamically in a stream or online query.

Incremental O(α(n)) vs Full O(V + E)

• Union-Find: Adding an edge and checking if two nodes connect takes O(α(n)) ≈ O(1).
• BFS/DFS: Must re-traverse the graph from scratch on every new edge, costing O(E · (V + E)) = O(V · E + E²). Unusable for online edge streams!

2. What Can't You Do Without UF?

Exclusive Strengths: Problems that become intractable without Disjoint Sets.

Where UF Dominates BFS/DFS

• Kruskal's MST: Sort edges and test if adding edge forms a cycle in O(1). (BFS/DFS cycle check is O(V) per edge → O(E · V) vs O(E log E)).
• Real-Time Cycle Detection: If find(u) == find(v), edge (u, v) is instantly redundant.
• Offline Reverse-Time Queries: Turn edge deletions (e.g. crumbling grids, falling bricks) into additions by running time backwards!

3. What BFS / DFS Can Do That UF Cannot

Hard Limitations: Scenarios where Union-Find is fundamentally the wrong tool.

Where BFS / DFS Are Required

• Path Reconstruction: UF only tells you if two nodes are connected; it cannot produce the actual path or edge sequence.
• Shortest Paths / Step Distances: BFS guarantees the minimum hops in unweighted graphs; UF has no concept of distance.
• Directed Graphs: Standard UF only models symmetric equivalence relations (A ~ B ⟺ B ~ A). It cannot model DAGs, topological sort, or SCCs (Tarjan/Kosaraju).

LPS Array (Longest Proper Prefix which is also Suffix)

Use when: preprocessing a search pattern for KMP, detecting periodic repeating substrings, or finding the longest prefix that is also a suffix.

Why it works & Visual Trace

For a pattern string pat, lps[i] stores the length of the longest proper prefix of pat[0..i] that is also a suffix of pat[0..i]. A proper prefix cannot be the whole string. Using pointer k for the prefix length and i for the suffix end, we extend matches in O(1) and roll back k = lps[k - 1] on mismatches without retreating i.

lps[i] = max length L
